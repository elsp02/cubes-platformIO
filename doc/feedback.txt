level_1: baseplate and one cube
- baseplate initiates tree detection
- cube sends identified tree payload
- baseplate tries to send cmd_feedback
- cube sends ack_feedback signal

level 2: cube sends cmd_feedback to children and receives ack and sends ack_finished to baseplate

level 3: send predefined feedback frame (2 bytes long with sync, len , feedback_payload and crc) to child and child checks if corect frame. if so relay feedback frame to children 

level 4: send predefined feedback frame with id of all three cubes and cube should identify if own id is contained in the frame if so, serial print U if not X, turn on LED

level 5: feedback loop only if payload changed or heartbeat, three different feedback payloads

level 6: feedback loop retry only when baseplate receives not CFF



final: target tree with NODE containing the Type of block (appearance) in the first 4 bits of one byte (e.g. 00001111). NODE_ID of a cube has also these 4 bits and then 4 individual bits for identify this individual node/cube (e.g. 10001111)
        -> how many types and ids can be created then (type= 16, id=16 => enough for my prototype)
      target tree comparison: compare just the first four bits to see if one cube is placed at the correct position, because just type matters here.

      LED FEEDBACK for cubes:
      - cube present + invalid -> red - add to feedback payload
      - cube present + correct + not already in last cycle -> green - add to feedback payload
      - cube present + correct + already in last cycle -> turn off 
      - cube present + invalid + already in last cycle -> red - add to feedback payload
      - cube dissapears - gone

      LED STATE for cubes 
      - green: 0x01
      - red: 0x02

     Cube invalid for visualization:
     - error_none = 0x00
     - error_wrong_id/type = bit 0 (1 << 0)
     - error_wrong_parent = bit 1 (1 <<1)
     - error_wrong_port = bit 2 (1<<2)
     - erron_wrong_orientation = bit 3 (1<<3)

     typedef struct{

     }compare_entry_t
